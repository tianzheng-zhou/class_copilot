## 1. 需求维护规则

- `F-01～F-37`：已有功能，编号与功能文档一致。拆分或删除时保留原编号及变更说明。
- `G-xx`：已观察到的实现差异或需要进一步复测的风险，不自动等于新版本需求。
- `D-xx`：影响重构范围的产品决策。
- `NFR-xx`：非功能需求草案。
- `AC-xx`：验收用例；确认目标行为后再判定通过/失败。
- `NEW-xx`：新增功能，从 `NEW-001` 开始。
- 重构决定填写“保留 / 修改 / 删除 / 待定”，不要将“当前存在”直接视为“必须保留”。

建议优先级：P0=核心使用闭环或数据完整性；P1=主要体验和稳定性；P2=辅助能力。下表优先级仅为讨论起点，可直接修改。

## 2. 产品目标与典型场景

### 2.1 目标草案

1. 用户在课堂中能持续获得可读的转写和参考问答。
2. 用户可以用课堂上下文继续提问，明确感知生成中、成功和失败。
3. 课堂结束后记录可查找、可导出、录音可取回。
4. 录音、连接和任务状态一致，出现故障时能知道保存了什么、还缺什么。
5. 完整重构时可按明确决定迁移已有课程、会话、问答、聊天和录音。

这里未预先限定新框架、模型供应商、数据库、部署方式或界面布局；这些应服务于确认后的需求。

### 2.2 用户场景

| 场景 | 使用者意图 | 当前路径 | 关键约束 |
| --- | --- | --- | --- |
| 第一次使用 | 配置并开始记录第一节课 | 配置Key和音源 → 创建课程 → 监听 | 本机音频设备和网络可用 |
| 线下课堂 | 采集教师讲话并自动问答 | 麦克风 → 转写 → 自动检测/答案 | 没有说话人或教师过滤 |
| 线上课程 | 记录电脑播放的音频 | 系统回环 → 同一流水线 | 实际目前始终读取默认扬声器 |
| 课堂追问 | 对概念继续解释 | 主动提问 → 选择模式和思考开关 | 当前必须保持监听 |
| 课后复习 | 找到记录、查看和导出 | 历史列表 → 详情 → Markdown/MP3 | 不可续聊、不可编辑 |
| 调试转写 | 用本地样本重复运行 | 开启调试文件源 → 路径 → 监听 | 需要ffmpeg；按实时节奏处理 |

## 9. 旧数据迁移与兼容需求草案

以下仅在决定保留历史数据时适用，尚未执行迁移。

1. 从数据库、配套加密密钥、录音文件制作一致副本，在副本上演练；明确最终切换时如何停止旧版本写入。
2. 保留课程和会话关联、名称、起止时间、状态、所有最终转写、问题上下文与置信度、全部答案类型、完整聊天角色和模型名。
3. 如果更换ID格式，建立旧新映射；如果保留ID，验证外键和唯一性。
4. 明确 `date` 与UTC时间/本地日期的映射；转写相对时间和绝对时间不能无依据互转。
5. 验证MP3文件数量、大小或校验和与会话对应；单独报告缺失文件、孤立文件和空元数据。
6. 对Key选择“保留并转换加密”或“要求重新填写”；不能只复制密文而丢弃配套密钥。
7. 处理旧 `language`、已废弃设置和非法值；记录默认回填规则，不静默改变语言或音源。
8. 迁移前后按表计数、抽取典型详情/导出比对；旧数据未存的信息保持未知，不能伪造生成模型、来源设备或任务结果。
9. 在完成验收和确认保留期前保留可回滚副本；是否兼容旧HTTP/WS协议单独决定，数据兼容不等于协议兼容。
