# 新版实施与验收记录

日期：2026-09-18。分支：`refactor/next`。范围：新版产品需求 R-01～R-11；不迁移旧数据，不读取旧凭据，不使用旧录音。

## 实现交付

- `backend/`：Python 3.12、FastAPI、SQLAlchemy Core、Alembic；冻结初始迁移、关系约束、独立数据目录和进程锁。
- `web/`：React 19、TypeScript、Vite、TanStack Query；课堂列表、三栏工作台、设置、音频/总结/任务侧栏。
- 50 个 HTTP 业务操作和 1 个 SSE 操作；公共 DTO、请求头约定和错误结构进入 OpenAPI，前端类型由其生成。
- 音频上传、真实设备适配器、先落盘再识别、分块去重、补识别、同流电平、短尾段、自动停止、MP3/原件下载和播放定位。
- 持久任务、原子业务与事件提交、幂等命令、乐观并发、取消/重试、模式切换、生成版本和检查点。
- 问题检测、参考答案、课后聊天、分段总结、输入预算、覆盖范围、缺口和总结过期判断。
- 刷新/多标签/SSE 游标恢复、完整导出、活动删除保护、失败清理重试、进程中断恢复。
- 明确保存/取消设置、未保存离页提醒、中英文界面、三种主题、窄窗口面板、键盘焦点管理。
- 安装/启动/检查/诊断/长音频检查脚本、锁文件和 GitHub Actions 验证配置。

运行方法见 [README](../README.md)。默认地址为 `http://127.0.0.1:29038`，运行数据默认在 `data/next/`。两个旧源码/构建目录和旧根虚拟环境不用于新版。

## 真实验收的剩余条件

1. 用户在新版设置中配置自己的百炼区域、工作空间地址和 Key，并主动执行连接测试。没有读取或复用旧 Key。
2. Ubuntu 安装 `pulseaudio-utils` 后，以两个可辨的麦克风和两个系统输出逐个验证来源、电平和音频内容。
3. 使用获准的中文、英文、混合、静音和边界样本测识别质量、延迟、限流和重复讲解；当前没有真实质量数值。
4. 执行真实 4 小时录音/识别，以及设备拔出、磁盘空间故障和进程终止演练。合成音频加速检查不能替代该项。

## 实施取舍与维护

- 核心边界保留，Python 文件按职责平铺，避免只为目录层级增加包装类。
- 关系列与 SQLite 唯一约束负责完整性，可演进字段存 JSON；后续 schema 修改增加 Alembic 迁移，不修改已发布的 0001。
- 上传先做本地校验，第一次分析固化识别配置；实时录音在新来源开始时固化。任务重试沿用输入/模型快照，可使用当前凭据。
- SQLite 是任务事实来源；内存仅存运行句柄和有界实时草稿。客户端每标签一条 SSE，实体变化使查询缓存刷新，分页历史仍可继续加载。
- 输入预算采用保守 UTF-8 字节上界；真实供应商 usage 按返回值记录，未知值不编造费用。
- 本轮未创建提交、未发布服务到公网、未推送远程、未切换主线。
