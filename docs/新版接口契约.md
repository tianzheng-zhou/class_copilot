# Class Copilot 新版接口契约

版本：0.1；日期：2026-09-18；状态：已实现；以 [实施记录](实施记录.md) 标注实际验证范围。

本契约服务于 [新版产品需求](新版产品需求.md)，内部实现见 [新版技术设计](新版技术设计.md)。旧 `/api` 与 `/ws` 无兼容承诺；不要求旧前端连接新版。实现已由 Pydantic/OpenAPI 生成 TypeScript 类型，并在 CI 检查导出差异，避免前后端分别手写一套类型。

## 1. 统一约定

- 基础路径 `/api/v1`；字段 `snake_case`；ID 为 UUID 字符串，格式非法返回 422，不存在返回 404。
- 时间为 UTC RFC3339，带 `Z`；时长/音频偏移为整数毫秒，均相对于明确的 `source_id`。不混用 epoch 和音频偏移。
- 字符串先去首尾空白再校验；禁止未知写入字段；严格区分省略、null、空串、布尔与数字。
- `PATCH` 的省略字段不修改；只有声明可空的字段允许 null。`custom_title=null` 恢复默认名称，其余名称不可空。设置的嵌套对象按叶字段合并后整体校验，不因只改一个 models 字段就清空其他模型。
- 同步查询/变更 200，创建普通资源 201，异步工作 202，无响应体删除 204；本节信封不套在 204、文件下载或 SSE 上。
- 每个响应有 `X-Request-ID`，错误不包含 Key、完整上游响应或磁盘路径。
- 同源访问；写请求携带 bootstrap 返回的 CSRF token（`X-CSRF-Token`）；服务校验 Origin/Host。CORS 不开放任意来源。

成功响应：

```json
{
  "data": {"id": "8dbd3a38-bc58-4776-8179-4f37fe74b312", "revision": 1},
  "meta": {"request_id": "req-123"}
}
```

列表的 `data` 为 `{"items":[],"next_cursor":null,"total":0}`。默认 limit=50，范围 1～200；next_cursor 不透明，绑定筛选和排序；改变筛选后不得沿用旧游标。课堂按 `(created_at DESC,id DESC)`，子内容按来源/片段或消息序号排序。分页不是无限加载全部记录。

异步接受响应：

```json
{
  "data": {
    "job": {"id": "aefad706-a078-4c07-a41c-e74c4d420b0a", "kind": "generate_answer", "state": "queued"},
    "resource": {"type": "answer_version", "id": "df229fec-97d1-42ed-a652-de6dd92eb55f"}
  },
  "meta": {"request_id": "req-124"}
}
```

文中 Job 简写示例只展示关键字段；正式 DTO 必须包括第 8 节字段。202 表示已持久化接受，不表示模型已成功或音频已开始录制。

### 1.1 幂等与并发

- 所有创建/执行型 POST 必须携带 `Idempotency-Key`，为客户端生成 UUID；DELETE 同样要求。PATCH 通过 `If-Match: "revision"` 做乐观并发控制。
- 同一键同一规范化请求返回原状态码和结果，设置 `Idempotent-Replayed: true`；同一键换方法/路径/请求体返回 409 `idempotency_conflict`。上传请求比较实际文件校验和及元数据。
- 幂等结果至少保留 24 小时。客户端超时只重试同一键，超过有效期后查询资源并交由用户重新操作，不自动用新键再发一次。
- `GET /commands/{key}` 查询已保存的原响应状态码、结果和资源 ID；不存在返回 404 `command_unknown`，不能据此证明过期命令从未执行。
- 在同一事务登记业务变更、任务、事件和命令结果；同键请求并发时只允许一个提交，另一个重放结果或返回 409 `command_in_progress` 并提示稍后查询。
- 需要 If-Match 而未提供时返回 428；版本不一致返回 412 `revision_conflict`，附当前 revision。课堂 metadata revision 与子内容 content_revision 分开，新增转写不造成改名冲突。
- 浏览器离线时不缓存待发送命令；恢复后先读取状态。

### 1.2 错误

```json
{
  "error": {
    "code": "audio_busy",
    "message": "另一项音频处理尚未结束",
    "request_id": "req-125",
    "retryable": false,
    "details": {"lesson_id": "8dbd3a38-bc58-4776-8179-4f37fe74b312"}
  }
}
```

| HTTP | code 示例 | 语义 |
| --- | --- | --- |
| 403 | `origin_rejected / csrf_invalid` | 不允许的访问来源或无效写入令牌 |
| 404 | `not_found / command_unknown / audio_missing` | 资源、命令记录或音频不存在 |
| 409 | `name_conflict / audio_busy / job_busy / lesson_busy / lesson_deleting / idempotency_conflict / command_in_progress` | 当前状态冲突，不是服务崩溃 |
| 410 | `resource_deleted` | 已知资源处于删除终态 |
| 412 / 428 | `revision_conflict / revision_required` | 更新版本冲突或缺失 |
| 413 / 415 | `file_too_large / unsupported_audio` | 上传超限或格式不支持 |
| 422 | `validation_error / no_transcript / invalid_selection / invalid_audio / duration_exceeded / model_capability_unsupported` | 数据/能力不符合契约 |
| 429 | `local_capacity_exceeded` | 本地任务或连接上限，附 Retry-After |
| 503 | `provider_not_configured / audio_unavailable / storage_unavailable` | 前置资源不可用 |
| 500 | `internal_error` | 脱敏内部错误，使用 request_id 定位 |

模型任务开始后的鉴权、限流、超时、解码等错误写入 Job.error 并推送事件，不把已返回的 202 改成 HTTP 错误。错误 code 为稳定英文标识；界面根据 code 本地化。

## 2. 引导、课程与课堂

以下路径省略 `/api/v1`。

| 方法与路径 | 输入 | 结果与规则 |
| --- | --- | --- |
| GET `/health` | 无 | 200：版本、就绪状态；不返回凭据或课堂正文 |
| GET `/bootstrap` | 无 | 200：CSRF token、配置状态、活动音频槽位、capabilities、event_cursor |
| GET `/commands/{key}` | 幂等键 | 200：已保存命令结果；见 1.1 |
| GET `/courses` | cursor, limit | Course 分页 |
| POST `/courses` | name | 201 Course；长度 1～100；重名 409 |
| PATCH `/courses/{id}` | name + If-Match | 200 Course |
| DELETE `/courses/{id}` | 无 | 空课程 204；有课堂 409 |
| GET `/lessons` | course_id?, q?, date_from?, date_to?, timezone?, cursor, limit | LessonListItem 分页，日期见下文 |
| POST `/lessons` | course_id, custom_title?, automation_mode? | 201 Lesson；不开始录音、不调用模型 |
| GET `/lessons/{id}` | 无 | 200 Lesson 元数据 |
| PATCH `/lessons/{id}` | custom_title? + If-Match | 200 Lesson；自定义名称 1～200 或 null |
| PUT `/lessons/{id}/automation` | mode + If-Match | 200 Lesson；使用课堂 metadata revision，与模式任务边界原子更新 |
| GET `/lessons/{id}/snapshot` | 无 | 课堂恢复快照，见第 9 节 |
| DELETE `/lessons/{id}` | 无 | 202 delete_lesson Job；有活动任务拒绝；重复查询已删除资源 410/404 |

`PUT automation` 不额外需要幂等键，相同 If-Match 再次提交会得到 412，客户端读取状态确定是否已生效。

日期条件为本地日历日期 `YYYY-MM-DD`，两端均包含；必须同时提供有效 IANA timezone。服务端换算 UTC 半开区间 `[from 当日00:00,to次日00:00)`。只有一端也可查询；q 最长 200，查询课堂显示名称或课程名，不宣称全文检索。

Course：`id,name,lesson_count,revision,created_at,updated_at`。

Lesson：`id,course_id,course_name,custom_title,display_title,lifecycle,automation_mode,automation_revision,content_revision,revision,created_at,updated_at`；附 `source_count,transcript_count,question_count,active_jobs,audio_activity,latest_summary_id` 用于展示。不存在“必须录音中才可聊天”的字段限制。

## 3. 音源、录音和导入

| 方法与路径 | 输入 | 结果与规则 |
| --- | --- | --- |
| GET `/audio/devices` | kind=microphone/loopback | 设备列表及 unavailable_reason；ID 指向实际设备 |
| POST `/audio/tests` | kind, device_id | 202 test_audio Job；5 秒测试；音频槽位忙时 409 |
| GET `/lessons/{id}/sources` | cursor, limit | AudioSource 分页 |
| POST `/lessons/{id}/recordings` | kind, device_id, auto_stop_minutes? | 202 start_source Job + AudioSource ID；全局槽位原子预留 |
| GET `/sources/{id}` | 无 | AudioSource，含采集/转写/资产状态 |
| PATCH `/sources/{id}` | auto_stop_minutes + If-Match | 仅 capturing 可改；null 为不主动计时，仍有 4 小时上限 |
| POST `/sources/{id}/stop` | 空对象 | 202 finalize_source Job；停止只控制此来源，不作用于当前其他来源 |
| POST `/lessons/{id}/uploads` | multipart 的 file | 201 AudioSource(kind=upload)；上传成功还未开始分析；第一次分析时固化识别配置 |
| POST `/sources/{id}/analysis` | generate_summary?, include_chat_in_summary? | 202 transcribe_source Job；仅上传或未完成来源；使用课堂当前模式 |
| GET `/sources/{id}/segments` | cursor, limit | 该来源最终转写分页，含未识别 gap 范围 |
| GET `/assets/{id}/content` | download? | 200/206 音频；可供播放器 Range 和下载 |

创建录音请求：

```json
{
  "kind": "loopback",
  "device_id": "opaque-device-id",
  "auto_stop_minutes": 45
}
```

- kind 只允许 microphone/loopback；指定 device_id 必须存在且类型相符。设置页选“默认设备”时，在开始操作中解析成具体设备 ID 并显示。
- start_source 在捕获槽位成功后准备硬件，成功使来源变成 capturing，启动失败释放槽位并标记 failed。返回 202 时 UI 不提前宣称录音已开始。
- `stop` 对 preparing/capturing/finalizing 幂等；准备中收到停止需取消打开设备。已 ready/interrupted/failed 时返回 200 当前来源及原收尾 job（可空），不新建录音或任务。
- 单次自动停止时间范围 1～240 分钟；改成早于当前采集时长立即进入收尾。来源模型/音源不可在 PATCH 中修改。
- test_audio 使用同一槽位；可通过任务取消提前结束。测试数据只发电平事件，不留音频文件、不调用云端。
- 上传不接收绝对路径或外部 URL。文件类型与时长解码验证通过才返回 201；同课堂校验和重复返回 409 `duplicate_audio` 和已有 source_id。上传中断清理临时文件，完整上传才创建可见来源。
- 分析请求 `generate_summary` 默认 true，`include_chat_in_summary` 默认 false。音频实时录制时不能用此接口重复分析；已全部成功的来源返回 409 `already_processed`。
- 失败或取消后重新分析只补未完成块；已有成功块不调用云端、不重复创建片段。任务 options 中保存自动总结选择。
- 文件上传完成前的取消由中断 HTTP 上传实现；之后分析取消通过 Job 接口。已接收源文件不因分析取消删除。
- 资产 role 为 original/playback；只暴露资产 ID、MIME、大小、状态和下载地址，不返回磁盘路径。MP3 未封装完成时不可用；恢复音频可为 partial。

AudioSource：`id,lesson_id,ordinal,kind,device_label,original_filename,capture_state,transcription_state,revision,settings_revision,started_at,stopped_at,stop_at,duration_ms,captured_ms,transcribed_ms,gap_ranges,assets,active_job_ids,error`。字段不适用时明确 null。

## 4. 转写、模式与问题

| 方法与路径 | 输入 | 结果与规则 |
| --- | --- | --- |
| GET `/lessons/{id}/transcripts` | source_id?, cursor, limit | TranscriptSegment 分页 |
| GET `/lessons/{id}/questions` | cursor, limit | Question 分页，带答案版本摘要 |
| POST `/lessons/{id}/question-detections` | segment_ids | 202 detect_questions Job；手动检测 |
| POST `/lessons/{id}/direct-answers` | segment_ids, style?, language?, model_role? | 202 generate_answer Job + Question ID；直接对片段生成参考答案 |
| GET `/questions/{id}` | 无 | Question 及引用片段、答案版本列表 |
| POST `/questions/{id}/answers` | style?, language?, model_role? | 202 generate_answer Job + AnswerVersion ID |
| GET `/answers/{id}` | 无 | 单个答案版本，含部分结果和状态 |

TranscriptSegment：`id,lesson_id,source_id,source_ordinal,ordinal,start_ms,end_ms,text,model,revision,created_at`。时间为音频块范围；`end_ms >= start_ms >= 0`。没有最终成功结果就不存在此实体，识别草稿走临时事件。

segment_ids 必须为本课堂已有的 1～100 个最终片段，服务端去重后按课堂来源顺序排序；未知或跨课堂片段返回 422 `invalid_selection`。超出上下文预算返回可理解错误，不偷偷只回答其中一半。

Question：`id,lesson_id,text,origin(auto/manual_detection/direct),segment_ids,confidence,created_at,revision,answer_versions`。confidence 对直接回答为 null；结构化检测结果必须在服务端验证。

AnswerVersion：`id,question_id,version,style(brief/detailed),language(zh/en/bilingual),model,content,state,job_id,basis_revision,context_coverage,error,revision,created_at,finished_at`。可读所有历史版本，默认版本由“最近 completed”派生。

三种模式均允许手动操作。自动检测按课堂隔离冷却和去重；模式切换具体队列语义见产品 R-05。HTTP 请求不等待完整检测/生成结果。

答案未传 style/language 时读取已保存的生成默认值；未传 model_role 时用 models.answer。显式 model_role 仅接受 fast/quality，分别使用 models.chat_fast/models.chat_quality；这只影响本次任务，不修改默认设置。

## 5. 聊天与总结

| 方法与路径 | 输入 | 结果与规则 |
| --- | --- | --- |
| GET `/lessons/{id}/chat-turns` | cursor, limit | ChatTurn 分页，包含所有回复尝试 |
| POST `/lessons/{id}/chat-turns` | content, model_role?, thinking? | 202 chat_reply Job + ChatTurn ID；原子保存用户和回复占位 |
| GET `/chat-turns/{id}` | 无 | ChatTurn 及回复版本 |
| POST `/chat-turns/{id}/replies` | model_role?, thinking? | 202 新回复尝试；不重复用户消息 |
| GET `/lessons/{id}/summaries` | cursor, limit | SummaryVersion 分页 |
| POST `/lessons/{id}/summaries` | include_chat?, language?, model_role? | 202 summarize_lesson Job + SummaryVersion ID |
| GET `/summaries/{id}` | 无 | 总结内容、状态、覆盖、是否有新内容 |

聊天 content 长度 1～20,000 字符，还需满足总模型输入预算；model_role 为 fast/quality，默认 fast；thinking 为布尔，默认 false。思考请求不代表返回或保存模型完整推理过程，用户可见内容以最终回复为准。

ChatTurn：`id,lesson_id,ordinal,user_content,created_at,replies,selected_reply_id,revision`。ChatReply：`id,turn_id,attempt,content,state,model,thinking,job_id,basis_revision,context_coverage,error,revision,created_at,finished_at`。

同课堂已有非终态 chat_reply 时，新的发送/重新回答返回 409 `job_busy`。重新回答已有旧问题默认使用该问题之前的对话和当前课堂内容；不会把后续对话放到旧提问之前。新回复产生后，后续已有消息不自动重算，UI 标明回复是在之后重新生成。

总结必须有最终转写；include_chat 默认 false。未传 language 时用 generation.language（出厂默认 zh），未传 model_role 时用 models.summary；显式 fast/quality 映射同答案接口。无转写返回 422 `no_transcript`。

SummaryVersion：`id,lesson_id,version,content,state,include_chat,language,model,job_id,basis_revision,context_coverage,content_signature,is_stale,error,revision,created_at,finished_at`。is_stale 根据实际依赖内容签名计算，生成总结本身不让其过期。

context_coverage 统一包含 `source_ranges,chat_turn_ids,answer_version_ids,gaps,truncated,description`。source_ranges 每项为 source_id、起止片段序号和起止毫秒；非连续选择拆成多个范围，不把缺口当作已覆盖。内部 input_snapshot 保留完整实体 ID 集合，公共接口用这些紧凑范围表达覆盖。

## 6. 设置和供应商

| 方法与路径 | 输入 | 结果与规则 |
| --- | --- | --- |
| GET `/settings` | 无 | 公开设置、revision、逐类生效提示；无 Key 明文 |
| PATCH `/settings` | 一个或多个设置字段 + If-Match | 200 完整新设置；全部校验后原子保存 |

| detection.confidence_threshold | 数字 0～1，默认 0.7 | 下一检测任务 |
| detection.cooldown_seconds | 整数 0～120，默认 10 | 下一检测任务 |

## 7. 导出与清理

| 方法与路径 | 输入 | 结果与规则 |
| --- | --- | --- |
| GET `/lessons/{id}/export` | format=markdown | 200 UTF-8 Markdown 附件 |
| GET `/jobs` | lesson_id?, state?, cursor, limit | Job 分页；含删除后仍保留的清理任务 |
| GET `/jobs/{id}` | 无 | Job 详情、进度和输出资源 |
| POST `/jobs/{id}/cancel` | 空对象 | 202/200 Job；见第 8 节 |
| POST `/jobs/{id}/retry` | 空对象 | 202 新 Job；原任务不改写 |

导出使用同一读事务得到一致的数据快照；包含所有最终转写、问题、答案尝试、用户消息、回复尝试和总结，按产品 R-09 保留未完成状态。文件名提供 UTF-8 Content-Disposition，禁止从标题拼接文件系统路径。

音频不嵌进 Markdown，导出列出音频名称、时长、来源及可用性；音频下载使用资产接口。删除中的课堂禁止新增任务和导出；其清理进度可以通过 Job 查询。

## 8. 任务契约

Job：`id,kind,state,lesson_id,source_id,parent_id,retry_of,resource,progress,created_at,started_at,finished_at,cancel_requested,error,revision`。

progress 为 `{"phase":"transcribing","completed":12,"total":40,"unit":"chunks"}`；total 未知时为 null，不伪造百分比。总结可按 phases 显示提炼和合并；音频进度另有毫秒数。Job.error 包含 `code,message,retryable,details`，不返回上游密钥或请求正文。

| kind | 可取消 | retry 行为 |
| --- | --- | --- |
| start_source | 用 source/stop | 不自动重开设备；用户显式重新开始录音 |
| test_audio | 是 | 再测 5 秒，不留音频 |
| transcribe_source | 是；实时采集先 stop | 只处理未完成块，仍受全局音频槽位约束 |
| detect_questions | 是 | 同一输入快照重新检测，幂等去重 |
| generate_answer | 是 | 新答案尝试，保留旧部分内容 |
| chat_reply | 是 | 原 ChatTurn 下新尝试，不复制用户文字 |
| summarize_lesson | 是 | 新总结版本，默认仍使用原输入快照；要覆盖新内容使用 summaries POST |
| finalize_source | 否 | 继续修复/封装本地已保存音频；不重开采集 |
| delete_lesson | 否 | 继续未完成清理，文件已不存在视为已完成 |
| test_provider | 是 | 再次显式测试；可能产生云端调用 |

取消 queued 任务可立即 200 cancelled；运行中先返回 202 cancelling；已终态返回 200 原状态。不支持取消返回 409 `job_not_cancellable`。retry 只接受 failed/cancelled/interrupted 且类型支持，其他返回 409 `job_not_retryable`。

手动 retry 沿用原输入/设置快照；如果凭据失效使用当前凭据并记录版本。模型或其他参数需变化时用相应资源的生成入口创建新任务。每次重试都显示可能重新调用云端，服务不在刷新后自动重试付费工作。

## 9. 快照、SSE 与事件

### 9.1 快照

`GET /lessons/{id}/snapshot` 的 data 包含：

```json
{
  "lesson": {"id": "8dbd3a38-bc58-4776-8179-4f37fe74b312", "revision": 3},
  "sources": {"items": [], "next_cursor": null, "total": 0},
  "transcripts": {"items": [], "next_cursor": null, "total": 0},
  "questions": {"items": [], "next_cursor": null, "total": 0},
  "chat_turns": {"items": [], "next_cursor": null, "total": 0},
  "summaries": {"items": [], "next_cursor": null, "total": 0},
  "active_jobs": [],
  "event_cursor": "database-epoch:1042"
}
```

每类最多最新 100 项，展示顺序为正序，next_cursor 指向更早内容；常规子资源分页使用相同“从新向旧取页、页内正序”的约定。UI 必须显示还有更多历史，不能以快照只含尾部为由隐藏旧转写。快照各资源和事件游标来自同一读事务；局部实体包含完整 DTO，此处为简写。

### 9.2 事件连接

`GET /events?after={cursor}`，`Content-Type: text/event-stream`，`Cache-Control: no-cache`。首次用 after；自动重连的 `Last-Event-ID` 优先。无两者时从当前水位开始，因此页面必须先加载快照。

持久事件：

```text
id: database-epoch:1043
event: entity.updated
data: {"cursor":"database-epoch:1043","type":"transcript.created","lesson_id":"8dbd3a38-bc58-4776-8179-4f37fe74b312","entity_type":"transcript","entity_id":"d62b4c3c-98bc-42c3-9810-c8e103d87e1e","revision":1,"occurred_at":"2026-09-18T09:00:00Z","data":{"text":"示例转写内容"}}

```

SSE event 名持久变更统一为 `entity.updated` 或 `entity.deleted`，业务细分使用 JSON type；data 为完整实体 DTO，此处只展示 text 以便阅读。cursor 包含数据库 epoch 和递增序号，不能复用于新建数据库。

| JSON type | 归属和作用 |
| --- | --- |
| course.created / course.updated / course.deleted | 更新课程及计数 |
| lesson.created / lesson.updated / lesson.deleting / lesson.deleted | 课堂元数据、模式或删除状态 |
| source.created / source.updated | 音源、采集、转写进度、资产可用性 |
| transcript.created | 最终文本已经提交，可恢复 |
| question.created / question.updated | 检测结果和答案摘要 |
| answer.updated | 版本检查点或终态，完整 content 替换 |
| chat_turn.created / chat_turn.updated | 用户消息、回复关联或默认选择 |
| chat_reply.updated | 回复检查点或终态 |
| summary.updated | 总结检查点、终态或过期状态 |
| job.created / job.updated | 队列、运行进度、取消、错误和终态 |
| settings.updated / credential.updated | 脱敏配置版本变化，不携带 Key |

临时事件使用 `event: live`，不写 `id:`，JSON 为 `{"cursor":null,"type":"audio.level",...}`。类型包含 `audio.level / transcription.draft / generation.draft`，分别携带 source_id 或 job_id/entity_id 与递增的临时版本；收到更高 revision 的持久检查点后清除旧草稿。即使浏览器对无 id 的事件继承 lastEventId，也不得把它当新的持久事件。

心跳为 SSE 注释，每 15 秒发送一次。临时事件可丢弃、合并；持久事件不得因客户端慢而静默丢失，慢连接关闭后从游标恢复。每标签一条连接；不同课堂的事件按归属分发，不在当前聊天追加其他课堂内容。

### 9.3 游标失效和一致性

- 日志只保留最近 7 天、最多 100,000 条；游标早于窗口、属于另一 epoch 或超过当前水位时发送 `event: reset_required`，data 含原因，无持久 id，然后关闭连接。
- 客户端收到 reset_required 先调用 EventSource.close，再取快照重新连接，避免浏览器带旧 Last-Event-ID 无限自动重连。
- 持久事件至少一次投递。按 cursor 去重复；实体按 revision 覆盖，不能把重复文本 delta 追加两次。
- 删除事件携带 entity_id、最终 revision 和最小 tombstone。普通资源已删除时返回 404；仍在保留期的 tombstone 可返回 410。
- 快照后接续 events 表读取，提交发生在“读快照”和“连 SSE”之间也不会漏掉。内存唤醒只做优化，不作为唯一事件来源。
