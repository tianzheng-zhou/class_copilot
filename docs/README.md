## 如何用这些文档推进重构

1. 先阅读功能说明，核对是否覆盖需要的使用场景。
2. 在需求文档中逐项填写“重构决定”，使用“保留 / 修改 / 删除 / 待定”；新增需求从 `NEW-001` 编号。
3. 对标注为实现缺口的行为，填写期望结果；不必复制现有缺陷。
4. 根据决定更新验收用例，再确定架构、技术选型和实施顺序。
5. 后续实现以确认后的需求为准；这套“当前现状”文档保留为迁移和回归比对依据。
