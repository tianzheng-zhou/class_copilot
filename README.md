# Class Copilot — 独立重构

这是 `refactor/next` 分支，从功能与需求文档开始完整重构。

## 当前状态

- 新分支使用独立的提交历史，初始版本只有文档和 Git 基础配置。
- 旧代码完整保留在 `main`，本分支尚未实现新的业务功能。
- 首先修改需求文档，确定功能去留和验收条件，再确定架构与实施计划。

## 文档入口

| 文档 | 用途 |
| --- | --- |
| [项目文档索引](docs/README.md) | 基线说明、阅读顺序与验证记录 |
| [功能说明](docs/功能说明.md) | 旧版37项功能、页面、流程和限制 |
| [重构需求与验收](docs/重构需求与验收.md) | 填写功能去留、目标行为、待决策事项和验收条件 |
| [接口与数据字典](docs/接口与数据字典.md) | 旧版接口、配置和数据模型，仅作为设计与迁移参考 |

## 推进方式

1. 在需求文档的“重构决定/修改说明”列填写保留、修改、删除或待定。
2. 确定关键产品决策、数据迁移范围和验收要求。
3. 根据确认后的需求制定新版架构与分阶段实施计划。
4. 按功能阶段开发、验证并提交，完成验收后再确定如何切换主线。

独立历史与 `main` 没有共同祖先，后续不能按普通功能分支直接合并；正式发布时另行选择主线切换或显式合并无关历史的方式。
